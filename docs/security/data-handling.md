# سیاست داده و امنیت (وضعیت فعلی + تعهدات فازهای بعد)

## اصول

1. **کمینه‌سازی:** فقط داده لازم ذخیره می‌شود. تصویر عروس تنها پس از رضایت صریح.
2. **راز در کد نیست:** فقط env/مدیریت راز. `env.example` بدون مقدار حساس.
3. **لاگ بدون داده شخصی:** شماره موبایل ماسک‌شده، IP هش‌شده، کد OTP هرگز لاگ نمی‌شود
   (کلیدهای حساس در لاگر redact می‌شوند).
4. **کنترل دسترسی سمت سرور:** مخفی‌کردن UI جای Guard را نمی‌گیرد.
5. **تصاویر خصوصی:** ذخیره‌سازی عمومی ممنوع؛ URL امضاشده کوتاه‌عمر (فاز ۶).

## داده‌هایی که امروز ذخیره می‌شوند

| داده | محل | نگه‌داری |
| --- | --- | --- |
| شماره موبایل | `users.phone` | تا حذف حساب |
| هش کد OTP | `otp_challenges.code_hash` | پیشنهاد: پاک‌سازی رکوردهای منقضی > ۲۴ ساعت (job فاز ۱۶) |
| هش IP | `otp_challenges.request_ip_hash` | همان چرخه پاک‌سازی |
| رخداد audit | `audit_logs` | حداقل ۱ سال (نیازمند تأیید مالک) |

## الزامات فاز ۶ (تصاویر)

- آپلود مستقیم به storage خصوصی با presigned URL کوتاه‌عمر (≤ ۵ دقیقه).
- محدودیت نوع/حجم + بازرسی malware در صورت پشتیبانی زیرساخت.
- حذف EXIF/GPS؛ thumbnail در همان bucket خصوصی.
- رضایت نسخه‌دار (`consent_version`) برای: پردازش تصویر، ذخیره، اشتراک‌گذاری با مزون.
- رضایت **آموزش مدل** جداگانه و پیش‌فرض **خاموش**.
- حذف درخواستی کاربر: فایل اصلی + مشتقات + رکوردهای ارجاعی.

## بدهی‌های امنیتی شناخته‌شده

| بدهی | شدت | برنامه |
| --- | --- | --- |
| توکن در `sessionStorage` (XSS) | متوسط | ADR-0004 → کوکی HttpOnly + CSRF در فاز ۱۶ |
| بدون CSP سخت‌گیرانه | متوسط | فاز ۱۶ همراه با nonce برای Next |
| rate limit درون‌دیتابیسی | پایین | Redis در فاز ۷ |
| بدون dependency/secret scan پیشرفته | متوسط | CI فعلی سبک است؛ Snyk/CodeQL در فاز ۱۶ |

## خروجی AI

- برچسب اجباری: «پیش‌نمایش هوش مصنوعی؛ تضمین فیت/سایز/جنس پارچه نیست».
- `is_mock` در پاسخ سرویس و برچسب «آزمایشی» در UI؛ در production سرویس mock پاسخ
  نمی‌دهد (۵۰۳ با کد `PROVIDER_UNAVAILABLE`).
