# معیارهای پذیرش (خلاصه قابل اجرا)

هر معیار باید با **تست یا شاهد اجرایی** تأیید شود؛ وضعیت در گزارش فاز ثبت می‌شود.

## فاز ۱ — نیازمندی و UX (تکمیل‌شده)

- [x] journeys، route map، data dictionary، state inventory و acceptance criteria مستند شده‌اند.
- [x] design tokens (رنگ، گردی، سایه، فونت Vazirmatn) و اجزای پایه RTL ساخته شده‌اند.
- [x] هر صفحه حالت loading/empty/error/success/disabled دارد.
- [ ] بازبینی طراحی با کاربر واقعی مزون (نیازمند جلسه با مالک) — Blocked.

## فاز ۲ — Foundation

- [x] lint، type-check، تست در CI.
- [x] لاگ ساخت‌یافته با `requestId` و redaction.
- [x] اعتبارسنجی تنظیمات با fail-fast و ممنوعیت mock در production.
- [x] `/healthz` و `/readyz` با بررسی واقعی دیتابیس.
- [x] migration نسخه‌دار با checksum.
- [ ] Docker/local environment تأییدشده — Blocked (بدون Docker در محیط ساخت).
- [ ] OpenAPI خودکار — بدهی؛ سند دستی موجود.

## فاز ۳ — هویت و چندمستاجری

- [x] OTP با انقضا، سقف تلاش، cooldown و سقف ساعتی.
- [x] نقش‌ها، عضویت، انتخاب مزون فعال، audit trail.
- [x] تست منفی: کاربر مزون A به رکورد مزون B دسترسی ندارد (۴۰۴ بدون افشای وجود).
- [x] no-secret: کد خام ذخیره نمی‌شود؛ IP هش می‌شود؛ شماره در لاگ ماسک می‌شود.
- [ ] دعوت کارمند/لغو دسترسی/تغییر نقش — **گام بعد**.
- [ ] پشتیبانی از ۲FA و ابطال فوری توکن — فاز ۱۶.

## فاز ۶ — رسانه (پیش‌نیاز مسیر پرو)

- [ ] آپلود مستقیم با محدودیت نوع/حجم، storage خصوصی، URL امضاشده کوتاه‌عمر.
- [ ] رضایت نسخه‌دار + رضایت آموزش مدل (پیش‌فرض خاموش).
- [ ] حذف فایل و نسخه‌های مشتق، تست لینک منقضی.

## فاز ۸/۷ — AI

- [x] قرارداد مستقل ارائه‌دهنده + برچسب «آزمایشی» در خروجی mock.
- [ ] کلید ارائه‌دهنده، benchmark ۳۰–۵۰ لباس، ledger مصرف — Blocked به‌علت دسترسی.
