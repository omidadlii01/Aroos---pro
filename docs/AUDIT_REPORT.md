## ۳. محیط اجرا (محدودیت‌های واقعی)

| ابزار | وضعیت | اثر |
| --- | --- | --- |
| Node.js 22.22 / npm 10.9 | موجود | همه بسته‌های JS قابل نصب و تست |
| Python 3.11 | موجود | سرویس AI و pytest |
| Docker / docker-compose | **موجود نیست** | `infra/docker-compose.yml` نوشته شد اما **اجرا/تأیید نشد** |
| PostgreSQL server | **موجود نیست** (و apt به آینه دسترسی ندارد) | تست‌ها روی **PGlite (پستگرس واقعی WASM)** اجرا می‌شوند |
| Redis | موجود نیست | صف/نرخ‌محدودیت توزیع‌شده فعلاً پیاده نشده (بدهی فاز ۷) |
| شبکه | npm و PyPI و GitHub | دانلود وابستگی و CI ممکن است |

تصمیم مهندسی ناشی از این محدودیت در `docs/adr/0002` ثبت شد: کد دیتابیس با SQL
پارامتری و migration خالص Postgres نوشته می‌شود تا **همان کوئری‌ها** روی PGlite (تست)
و Postgres واقعی (staging/prod) اجرا شوند؛ ORM اختصاصی انتخاب نشد.

## ۴. نقشه معماری موجود (پس از این فاز)

```
Browser ──(same-origin /api/*)──▶ apps/web (Next.js 16, RTL)
                                   │ rewrite سمت سرور
                                   ▼
                          apps/api (NestJS 12, ESM)
                          ├─ ConfigModule (zod-like validation، fail-fast)
                          ├─ LoggerModule (JSON structured + redaction + requestId)
                          ├─ DatabaseModule (pglite | postgres, migrator نسخه‌دار)
                          ├─ AuthModule (OTP، JWT HS256، انتخاب مزون فعال)
                          ├─ TenantsModule (TenantGuard + نقش‌های مزون)
                          ├─ BoutiquesModule (CRUD مالك، چرخه وضعیت، audit)
                          ├─ AuditModule (audit_logs با requestId)
                          └─ HealthModule (/healthz، /readyz، /api/v1/meta)

                          services/ai (FastAPI) — آداپتور dev-watermark (is_mock=true)
```

جزئیات: [`docs/architecture/overview.md`](architecture/overview.md).

## ۵. ریسک‌ها و بدهی‌های شناسایی‌شده

| ریسک | شدت | وضعیت/برنامه |
| --- | --- | --- |
| RLS در تست‌ها اجرایی نمی‌شود (نقش superuser) | متوسط | policyها نوشته و وجودشان تست شد؛ اعتبارسنجی اجرایی نیازمند Postgres با نقش `bridalos_app` |
| توکن در `sessionStorage` (آسیب‌پذیر به XSS) | متوسط | ADR-0004؛ انتقال به کوکی HttpOnly + CSRF در فاز ۱۶ |
| آداپتور پیامک واقعی وجود ندارد | بالا | Blocked به‌علت دسترسی؛ `SMS_DRIVER≠dev` عمداً خطای پیکربندی می‌دهد |
| نرخ‌محدودیت OTP درون‌دیتابیسی است (بدون Redis) | متوسط | برای تک‌نمونه کافی؛ برای چندنمونه در فاز ۷ به Redis منتقل می‌شود |
| OpenAPI/Swagger تولید خودکار نشده | متوسط | `docs/api/endpoints.md` دستی و همگام با شواهد curl؛ برچسب «در انتظار» |
| E2E مرورگر (Playwright) ندارد | متوسط | پوشه `tests/e2e` رزرو شده؛ تست فعلی API سطح HTTP است |
| یکسان‌سازی تاریخ: نمایش شمسی با ICU | پایین | تست‌های تبدیل شمسی/میلادی موجود است |
| Docker/compose تأییدنشده | متوسط | Blocked در محیط؛ مالک باید روی ماشین با Docker اجرا کند |

## ۶. دسترسی‌ها و ورودی‌های لازم از مالک

1. **سرویس پیامک** (حساب تجاری + الگوی تأییدشده + کلید API) → فعال‌سازی واقعی ورود.
2. **ارائه‌دهنده AI** (کلید + مجوز تجاری + سیاست داده) → فاز ۷/۸ و benchmark ۳۰–۵۰ لباس.
3. **دامنه و میزبان staging** برای اجرای Docker/Postgres واقعی و اعتبارسنجی RLS.
4. **درگاه پرداخت sandbox** (فاز ۱۳) — هیچ پرداخت واقعی بدون قرارداد و تأیید.
5. **تصمیم مالک** درباره سیاست نگهداری تصاویر و متن رضایت نسخه‌دار (فاز ۶).

## ۷. کارهای انجام‌شده در این چرخه (خارج از فاز ۰، ایمن و برگشت‌پذیر)

- اسکلت monorepo، tsconfig مشترک، ESLint/Prettier، `.gitignore`، `env.example`، CI.
- `packages/contracts` با ۳۸ تست (اعتبارسنجی، پول ریال/تومان، تاریخ شمسی، OTP، نقش‌ها).
- `apps/api` با migrationهای `0001_init` و `0002_rls`، ۳۹ تست یکپارچه روی Postgres
  درون‌فرایندی، شامل تست منفی جداسازی tenant.
- `apps/web` با صفحات واقعی خانه/ورود/پنل، RTL و حالت‌های UI.
- `services/ai` با ۶ تست pytest و محافظت production.
- اعتبارسنجی واقعی HTTP: `/healthz`، `/api/v1/meta`، چرخه کامل OTP→مزون→مزون فعال.

## ۸. گام بعدی پیشنهادی

فاز ۱ (تثبیت نیازمندی/UX) تکمیل شد؛ برای ادامه پیشنهاد می‌شود فاز ۳ (دعوت کارمند،
لغو دسترسی، تغییر نقش) و فاز ۴ (کاتالوگ لباس + آپلود خصوصی تصویر) به ترتیب انجام شود،
زیرا مسیر عمودی «مزون → لباس → پرو → رزرو» به آن‌ها وابسته است. اجرای Docker و
اعتبارسنجی RLS نیز به‌عنوان گیت قبل از staging لازم است.
