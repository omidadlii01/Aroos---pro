# ADR-0002 — دسترسی داده SQL-first + تست روی Postgres درون‌فرایندی (PGlite)

- **وضعیت:** پذیرفته‌شده (2026-11-07)
- **زمینه:** در محیط ساخت، Docker و سرور Postgres موجود نبود؛ در عین حال محصول به
  Postgres، RLS، ایندکس و تراکنش واقعی نیاز دارد. mock کردن دیتابیس، تست را بی‌ارزش می‌کند.
- **تصمیم:**
  1. لایه دسترسی داده: SQL پارامتری با `SqlRunner` (دو پیاده‌سازی: `pglite` و `postgres`).
  2. migrationهای خالص `.sql` با ثبت checksum در `schema_migrations` (ضد تغییر گذشته).
  3. تست‌های یکپارچه روی **PGlite** (پستگرس WASM، همان SQL، بدون Docker).
  4. در staging/production همان migrationها روی Postgres واقعی اعمال می‌شوند.
- **پیامدها:**
  - ORM حذف شد؛ هزینه: نوشتن دستی کوئری و map کردن ردیف‌ها. سود: کنترل کامل روی SQL،
    سازگاری دو درایور، و نبود «جعبه سیاه».
  - RLS در PGlite با نقش superuser **اعمال نمی‌شود**؛ بنابراین policyها با تست
    `pg_policies` تأیید می‌شوند و اعتبارسنجی اجرایی به Postgres با نقش `bridalos_app`
    موکول است (ریسک ثبت‌شده).
  - اگر در آینده تعداد موجودیت‌ها زیاد شد، ورود Drizzle به‌عنوان لایه type-safe روی
    همان migrationها ممکن است؛ migrationها تغییر نمی‌کنند.
