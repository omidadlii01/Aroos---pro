# ADR-0005: رسانه خصوصی، بازکدگذاری تصویر و URL امضاشده

- **وضعیت:** پذیرفته‌شده (فاز ۴/۶)
- **تاریخ:** ۲۰۲۶-۱۱-۰۷
- **زمینه:** تصاویر لباس مزون و (در فازهای بعد) عکس شخصی عروس هرگز نباید در فضای عمومی و بدون کنترل دسترسی سرو شوند. الزام ۸ کارفرما: «تصاویر کاربر خصوصی است؛ storage عمومی ممنوع».

## تصمیم

1. **هیچ فایل تصویری با URL مستقیم و پایدار سرو نمی‌شود.** تنها راه دسترسی:
   `GET /api/v1/media/:id?expires=<unix>&token=<hmac>` که توکن آن
   `HMAC-SHA256(mediaId + "." + expiresAt, MEDIA_SIGNING_SECRET)` است.
2. **TTL کوتاه (پیش‌فرض ۳۰۰ ثانیه)**؛ API در هر پاسخ لیست/جزئیات، URL تازه می‌سازد.
   لینک منقضی یا دستکاری‌شده → `403` و فایل حذف‌شده → `404`.
3. **آداپتور storage پشت interface `MediaStorage`**: در محیط توسعه/تست `LocalMediaStorage`
   روی `.data/media` با محافظت در برابر path traversal و ممنوعیت صریح در `NODE_ENV=production`.
   آداپتور S3/MinIO (private bucket + presigned URL) پیاده‌سازی نشده و **blocked by access** است؛
   قرارداد `MediaStorage` برای همان امضا نوشته شده تا جایگزینی بدون تغییر سرویس‌ها ممکن باشد.
4. **بازکدگذاری اجباری تصویر** (`sharp`): تشخیص magic bytes، بازکدگذاری به JPEG کیفیت ۸۴،
   حداکثر ضلع ۲۰۰۰px، حذف کامل EXIF/GPS. پس از بازکدگذاری، MIME اعلام‌شده مشتری دور ریخته می‌شود.
   (تست: `catalog.test.ts` — MIME جعلی رد می‌شود و رشته EXIF ورودی در فایل ذخیره‌شده وجود ندارد.)
5. **حق انتشار اجباری:** بارگذاری بدون هدر `x-rights-attested: true` رد می‌شود و
   `rights_attested_at` در جدول `dress_media` ثبت می‌گردد (اثبات رضایت برای ممیزی).
6. **حذف نرم در DB + حذف فیزیکی فایل** هنگام `DELETE`؛ `checksum_sha256` برای جلوگیری از
   آپلود تکراری و ردیابی نگه‌داری ذخیره می‌شود.
7. عکس‌های عروس (فاز ۶) از همان مسیر عبور می‌کنند اما در جدول جداگانه با مالکیت کاربر
   و سیاست نگه‌داری/حذف مستقل ذخیره می‌شوند؛ تا آن زمان هیچ فیلد عمومی برای عکس عروس وجود ندارد.

## پیامدها

- لینک‌ها کوتاه‌عمرند؛ کش CDN باید `private` بماند (هدر `Cache-Control` همین را اعلام می‌کند).
- کلید `MEDIA_SIGNING_SECRET` (حداقل ۳۲ نویسه) بخشی از رازهای محیطی است؛ در غیر production
  مقدار موقت تصادفی ساخته می‌شود و در لاگ هشدار داده می‌شود.
- سرو تصویر کمی CPU مصرف می‌کند (HMAC + read)؛ در مقیاس، آداپتور S3 presigned این هزینه را حذف می‌کند.
- تحویل به کاربر ناشناس ممکن نیست؛ هر مشاهده نیازمند URL تازه از API است.
